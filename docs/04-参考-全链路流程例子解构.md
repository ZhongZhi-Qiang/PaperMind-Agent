# 学术研究 Agent 助手：从一条论文请求到知识沉淀的全流程解析

以"帮我 ingest 这篇论文 Attention Is All You Need，arXiv 1706.03762"为例，逐层拆解 Agent 的完整运行机制。

---

## 场景设定

用户 "李博" 是一名 AI 方向的研二学生，在前端聊天界面发送：

```
帮我 ingest 这篇论文 Attention Is All You Need，arXiv 1706.03762
```

以下是从这条消息发出到知识沉淀完成的**全链路执行过程**。

---

## 一、消息入口：前端 → FastAPI → AgentManager

### 1.1 前端发送

前端（Next.js 14）通过 SSE 流式请求发送到后端：

```
POST /api/chat
Body: { "message": "帮我 ingest 这篇论文...", "thread_id": "sess_001" }
```

### 1.2 AgentManager.astream() 接管

**源码位置：** `graph/agent.py`

`AgentManager` 是单例，`astream()` 是核心方法，按以下顺序执行：

```python
async def astream(self, message, thread_id, ...):
    # ① 构建 turn_messages
    turn_messages = []

    # ② 长期记忆检索注入
    if memory_backend == "v3":
        ctx = await _v3_recall_service.recall(message)
        turn_messages.append({"role": "system", "content": ctx["append_system_context"]})
        turn_messages.append({"role": "assistant", "content": ctx["prepend_context"]})

    # ③ 用户消息
    turn_messages.append({"role": "user", "content": message})

    # ④ 调用 agent graph
    async for event in agent.astream({"messages": turn_messages}, config={"thread_id": thread_id}):
        yield event  # 流式返回给前端

    # ⑤ 长期记忆 L0 捕获
    if memory_backend == "v3":
        await _v3_recorder.capture(thread_id, message, final_response)
```

## 二、安全检查：Guardian 门卫

### 2.1 before_agent：Prompt Injection 防御

用户消息进入 agent graph 后，第一个经过的是 `GuardianMiddleware`。

**源码位置：** `graph/guardian.py`

```python
class GuardianMiddleware(AgentMiddleware):
    async def abefore_agent(self, state, runtime):
        user_message = state["messages"][-1].content
        # 调用轻量 LLM 做二分类
        result = await self._classifier.ainvoke([
            SystemMessage(content=GUARDIAN_SYSTEM_PROMPT),
            HumanMessage(content=user_message),
        ])
        # 返回 "安全" 或 "危险"
        if "危险" in result.content:
            return {"messages": [AIMessage(content="该请求已被安全策略拦截。")]}
            # → 跳到 graph 终止节点，整个 agent 不执行
```

**分类器检查四类攻击：**
- Prompt Injection（忽略指令、角色扮演、泄露 system prompt）
- 敏感信息探测（API key、配置）
- 未授权操作（删文件、危险命令）
- 角色扮演攻击（DAN 模式、开发者模式）

**李博的消息**："帮我 ingest 这篇论文..." → 分类为"安全" → 放行。

### 2.2 Guardian 失败模式

| 模式 | 上游超时/报错时 | 适用场景 |
|------|---------------|---------|
| `closed`（默认） | 拦截，不执行 | 安全优先 |
| `open` | 放行 | 可用性优先 |

## 三、系统 Prompt 组装：Agent 的"人格"

### 3.1 build_system_prompt()

**源码位置：** `service/prompt_builder.py`

系统 prompt 由 6 个 Markdown 文件拼接而成：

```
┌─────────────────────────────────────────────────┐
│  SKILLS_SNAPSHOT.md    ← skills 摘要索引         │
├─────────────────────────────────────────────────┤
│  SOUL.md               ← 核心价值观与行为边界     │
├─────────────────────────────────────────────────┤
│  IDENTITY.md           ← "橘子助手"身份设定       │
├─────────────────────────────────────────────────┤
│  USER.md               ← 用户画像（如有）         │
├─────────────────────────────────────────────────┤
│  MEMORY_HINT.md        ← 记忆系统使用指南         │
├─────────────────────────────────────────────────┤
│  AGENTS.md             ← 工具协议 + Wiki 规范     │
└─────────────────────────────────────────────────┘
```

### 3.2 SOUL.md：五条核心价值观

```
1. 知识诚实 — 严格区分论文结论与 Agent 推断
2. 可追溯性 — 每个论断必须链接到论文/页面/工具结果
3. 结构化积累 — 知识沉淀为 wiki 页面，不随对话消亡
4. 最小假设 — 确认用户上下文后再决定抽象层次
5. 工程思维 — 像维护代码库一样维护知识库
```

### 3.3 IDENTITY.md：橘子助手

```
名字：橘子助手
定位：AI/Agent 方向研究生的学术研究助手
风格：沉稳、专业、直接，像靠谱的师兄
默认语言：中文，学术术语保留英文
```

### 3.4 AGENTS.md：操作规范

定义了 Wiki 优先、Skill 优先、来源优先、结构化积累、透明可审计五条原则，以及 13 个工具的使用协议和 6 个工作流规范。

## 四、长期记忆检索：RecallService.recall()

### 4.1 并行三层检索

**源码位置：** `memory_module_v3/retrieval/service.py`

用户消息发出后，`RecallService` 并行检索三个层级：

```python
async def recall(self, query):
    l1_task = asyncio.create_task(self._recall_l1(query))  # 原子事实
    l2_task = asyncio.create_task(self._recall_l2())        # 场景导航
    l3_task = asyncio.create_task(self._recall_l3())        # 用户画像
    return {"l1_facts": await l1_task, "l2_scenes": await l2_task, "l3_persona": await l3_task}
```

### 4.2 L1 混合检索（pgvector + tsvector + RRF）

```sql
-- 向量搜索（pgvector）
SELECT fact_id, content, 1 - (embedding <=> $1::vector) AS cosine_sim
FROM memory_v3.l1_facts WHERE embedding IS NOT NULL
ORDER BY embedding <=> $1::vector LIMIT 20;

-- 关键词搜索（tsvector）
SELECT fact_id, content, ts_rank_cd(content_tsv, plainto_tsquery('simple', $1)) AS rank_score
FROM memory_v3.l1_facts WHERE content_tsv @@ plainto_tsquery('simple', $1)
ORDER BY rank_score DESC LIMIT 20;
```

两路结果通过 RRF（k=60）融合排序。

### 4.3 注入到消息列表

检索结果被拆分为两部分注入：

```python
# L3 画像 + L2 场景导航 → system message
turn_messages.append({"role": "system", "content": """
<user-persona>李博是一名 AI 方向的研二学生...</user-persona>
<scene-navigation>
- transformer_architecture (15 facts) — 用户研究 Transformer 架构、self-attention 与位置编码
- bert_pretraining (12 facts) — 用户对比 BERT 与 GPT 的预训练策略
</scene-navigation>
"""})

# L1 相关事实 → assistant message
turn_messages.append({"role": "assistant", "content": """
<relevant-memories>
- [episodic] 用户导入了论文 Attention Is All You Need (Vaswani et al., 2017)
- [persona] 用户正在研究 Transformer 架构相关工作
</relevant-memories>
"""})

# 用户消息
turn_messages.append({"role": "user", "content": "帮我 ingest 这篇论文..."})
```

**最终 LLM 看到的消息序列：**

```

system:    <user-persona>...<scene-navigation>...
assistant: <relevant-memories>...
user:      帮我 ingest 这篇论文 Attention Is All You Need...
```

## 五、Agent Loop：LLM 如何"思考"和调用工具

### 5.1 ReAct 循环

Agent 是 LangChain `create_agent` 创建的 `CompiledStateGraph`，采用 ReAct（Reasoning + Acting）模式：

```
LLM 思考 → 决定调用工具 → 执行工具 → 结果返回 LLM → 继续思考 → ... → 输出最终回复
```

**LLM 自主决定**是调用工具还是直接回复。它看到 system prompt 中的工具描述和 SKILLS_SNAPSHOT，根据用户意图选择行动。

### 5.2 第 1 轮循环：读取 Skill

李博说 "ingest 论文"，LLM 识别到这匹配 `paper-ingest` skill。

**LLM 输出：**
```json
{
  "tool_calls": [{
    "name": "read_file",
    "args": {"path": "skills/paper-ingest/SKILL.md"}
  }]
}
```

**工具执行：** `ReadFileTool` 读取 `skills/paper-ingest/SKILL.md`，返回完整的 10 步工作流指令。

**LLM 现在知道了完整流程**，开始按步骤执行。

### 5.3 第 2 轮循环：注册源文件

**LLM 输出：**
```json
{
  "tool_calls": [{
    "name": "register_source",
    "args": {"url": "https://arxiv.org/pdf/1706.03762"}
  }]
}
```

**工具执行：** `RegisterSourceTool` 做三件事：
1. 计算 PDF 的 SHA-256 哈希（去重）
2. 下载 PDF 到 `raw/sources/1706.03762.pdf`
3. 追加记录到 `raw/sources/manifest.jsonl`

```jsonl
{"hash": "a1b2c3...", "path": "raw/sources/1706.03762.pdf", "url": "https://arxiv.org/pdf/1706.03762", "ts": "2026-06-08T14:00:05+08:00"}
```

### 5.4 第 3 轮循环：解析 PDF

**LLM 输出：**
```json
{
  "tool_calls": [{
    "name": "pdf_parser",
    "args": {"path": "raw/sources/1706.03762.pdf"}
  }]
}
```

**工具执行：** `PDFParserTool` 用 PyMuPDF 提取：
- 标题（第一页最大字体启发式）
- 作者（正则匹配）
- 摘要（"Abstract" 到下一个 section header 之间的文本）
- 全文（最多 30 页，清理 LaTeX 渲染产物）
- 截断到 50K 字符

**返回：** 结构化的论文信息（~15000 字符）。

### 5.5 ContextOffload 介入：压缩工具结果

`pdf_parser` 返回了 15000 字符，超过 `l1_size_threshold=3000`。

**wrap_tool_call 流程：**

```python
# 1. 收集 ToolPair 到缓冲区
pair = ToolPair(tool_name="pdf_parser", result="...", tool_call_id="call_001")
self._offload.add_tool_pair(pair)

# 2. 大小触发：15000 >= 3000 → 立即触发 L1
# → 后台 asyncio.create_task(self._run_l1([pair]))

# 3. 机械降级（当前轮返回，无 LLM 时的 fallback）
compressed = """
[Offloaded Tool Result | node: N/A]
Summary: [pdf_parser] Attention Is All You Need (Vaswani et al., 2017). The dominant sequence transduction models...
result_ref: refs/ref_abc123.md (read this file for full tool call and raw result)
"""

# 4. L1 完成后（有 LLM 时），get_compressed_result() 返回：
compressed = """
[Offloaded Tool Result | node: transformer-analysis-N1]
Summary: Transformer 架构论文，提出 self-attention 机制替代 RNN，WMT 2014 EN-DE 达到 28.4 BLEU
result_ref: refs/ref_abc123.md (read this file for full tool call and raw result)
"""
```

**后台 L1 LLM 摘要（异步，不阻塞响应）：**

```json
[{
  "tool_call": "pdf_parser: 解析 Attention Is All You Need 论文",
  "summary": "Transformer 架构论文，提出 self-attention 机制替代 RNN，WMT 2014 EN-DE 达到 28.4 BLEU",
  "score": 9,
  "tool_call_id": "call_001"
}]
```

完整结果存入 `refs/ref_abc123.md`，摘要存入 JSONL。

LLM 按 `paper-ingest` skill 的步骤 4-6，依次调用 `save_wiki_page`：

每个工具是 `BaseTool` 子类，定义 `name`、`description`、`args_schema`（Pydantic）和 `_run()` 方法。

### 7.2 工具安全拦截：HarnessSecurity

**源码位置：** `graph/harness_security.py`

每次工具调用前，`HarnessSecurityMiddleware.wrap_tool_call()` 做三重检查：

```python
async def awrap_tool_call(self, request, handler):
    # 1. 受保护文件路径
    if matches_protected_path(args):  # **/.env, **/*.key, **/.ssh/*
        return ToolMessage(content="[Harness 安全拦截] 访问受保护文件")

    # 2. 危险命令
    if matches_dangerous_command(args):  # rm -rf, DROP TABLE, /dev/sd
        return ToolMessage(content="[Harness 安全拦截] 危险命令")

    # 3. 自定义规则（热重载）
    if matches_custom_rules(tool_name, args):  # config/harness_rules.yaml
        return ToolMessage(content="[Harness 安全拦截] 违反自定义规则")

    # 通过 → 执行工具
    return await handler(request)
```

规则文件 `config/harness_rules.yaml` 支持热重载（修改后立即生效，无需重启）。

### 7.3 工具执行链

```
LLM 输出 tool_calls
    │
    ├─ Guardian（已通过，before_agent 只跑一次）
    │
    ├─ HarnessSecurity.wrap_tool_call()
    │   → 检查文件路径 / 危险命令 / 自定义规则
    │   → 拦截 或 放行
    │
    ├─ ContextOffload.wrap_tool_call()
    │   → 收集 ToolPair 到缓冲区
    │   → 压缩工具结果（机械降级 或 L1 摘要）
    │
    ├─ tool.execute()
    │   → 实际执行（PyMuPDF 解析 / 文件写入 / HTTP 请求等）
    │
    └─ 返回 ToolMessage（可能已压缩）
```

## 八、Skills 系统详解

### 8.1 Skill 是什么

Skill 不是代码，是**结构化的 Prompt 文档**。每个 Skill 是一个目录，包含 `SKILL.md`：

```
skills/
├── paper-ingest/
│   └── SKILL.md      ← 10 步论文导入工作流
├── paper-update/
│   └── SKILL.md      ← 论文更新工作流
├── wiki-ask/
│   └── SKILL.md      ← Wiki 增强问答
├── ideate/
│   └── SKILL.md      ← 研究灵感生成
├── wiki-lint/
│   └── SKILL.md      ← 知识库健康检查
└── ...
```

### 8.2 Skill 发现机制

**源码位置：** `tools/skills_scanner.py`

启动时扫描 `skills/*/SKILL.md`，解析 YAML frontmatter，生成 `SKILLS_SNAPSHOT.md`：

```xml
<skills>
  <skill name="paper-ingest" trigger="ingest, 导入, 论文导入">
    导入学术论文到 Wiki 知识库，自动创建论文/概念/方法/数据集/作者页面
  </skill>
  <skill name="wiki-ask" trigger="查询, 问答, wiki">
    Wiki 增强问答，BM25 + embedding 混合检索
  </skill>
  ...
</skills>
```

这个 snapshot 被注入到 system prompt 中，LLM 看到 trigger 关键词后，调用 `read_file` 加载完整的 SKILL.md。

### 8.3 Skill 如何指导 Agent

Skill 本质是**工具调用编排指令**。以 `paper-ingest` 为例：

```
Step 1: register_source(url) → 注册源文件
Step 2: pdf_parser(path) → 解析 PDF
Step 3: [LLM 内部分析] → 提取背景/方法/实验/贡献
Step 4: save_wiki_page(slug, type="paper") → 创建论文页面
Step 5: save_wiki_page(slug, type="concept") × N → 创建概念页面
Step 6: save_wiki_page(slug, type="author") × N → 创建/更新作者页面
Step 7: [条件] save_wiki_page(type="survey") → 3+ 同标签论文时
Step 8: [条件] save_wiki_page(type="comparison") → 用户确认时
Step 9: rebuild_index() → 重建索引
Step 10: append_log() → 审计日志
```

LLM 按步骤执行，每步自主决定具体参数（slug、content 等）。

### 8.4 retry-lesson-capture：失败学习机制

当任务首次失败、重试成功时，Agent 自动触发此 Skill：

1. 对比失败和成功的路径
2. 提炼可复用的教训（信号 → 替代方案 → 下次规则）
3. 写入当前 SKILL.md（带日期的教训条目）
4. 写入 `workspace/MEMORY.md`（跨 Skill 共享）

这让 Agent 能从错误中学习，下次遇到类似情况自动避免。

class QueryWikiTool(BaseTool):

三种模式：`hybrid`（默认）、`bm25`、`semantic`。

## 十、上下文管理：如何防止信息过载

### 10.1 三层上下文管理

```
┌─────────────────────────────────────────────────────────────┐
│  Layer 1: 长期记忆注入（每轮）                                │
│  ├─ L3 画像 → system message                                │
│  ├─ L2 场景导航 → system message                            │
│  └─ L1 相关事实 → assistant message                         │
│  → 让 LLM 知道"用户是谁、之前学了什么"                       │
├─────────────────────────────────────────────────────────────┤
│  Layer 2: 短期记忆压缩（Agent Loop 内）                      │
│  ├─ before_model: 两个独立操作                               │
│  │   → 摘要替换: context >= 50% 时按 L1 score 替换旧工具结果  │
│  │   → MMD 注入: 插入活跃任务的 Mermaid 流程图               │
│  │   → context >= 85%: 删除最旧 30% 消息                    │
│  │   → context >= 95%: 强制截断到 60%                       │
│  └─ wrap_tool_call: 压缩当前工具结果                         │
│  → 防止工具输出撑爆上下文窗口                                │
├─────────────────────────────────────────────────────────────┤
│  Layer 3: 对话压缩（可选）                                   │
│  └─ Summarization: 消息数 >= 50 时压缩为结构化摘要           │
│  → 释放上下文窗口                                            │
└─────────────────────────────────────────────────────────────┘
```

### 10.2 before_model 的作用域

`before_model` 在**每次 LLM 调用前**执行，操作的是**整个对话历史**（包括上一轮对话）：

```
消息列表:
┌─ 上一轮对话 ─────────────────────────────────────┐
│ user: "ingest 论文 Attention Is All You Need"    │
│ assistant: tool_calls: [register_source]          │
│ tool: "已注册, hash=abc123..."                    │
│ assistant: tool_calls: [pdf_parser]               │
│ tool: "Transformer 架构论文..." (15000 chars)     │ ← 可被 L3 压缩
│ assistant: "已导入论文..."                         │
└───────────────────────────────────────────────────┘
┌─ 当前轮 ─────────────────────────────────────────┐
│ user: "self-attention 和传统 attention 有..."     │
│ assistant: tool_calls: [query_wiki]               │
│ tool: "Self-attention 的 Q/K/V 来自..."           │ ← 当前轮，不压缩
└───────────────────────────────────────────────────┘
```

### 10.3 wrap_tool_call 的作用域

`wrap_tool_call` 只操作**当前这一次工具调用**：

```python
# pdf_parser 返回 15000 字符
# → 15000 >= 3000（大小阈值）→ 立即触发 L1 LLM 摘要
# → 当前轮返回机械压缩版本
# → 后台 L1 完成后，下一轮 before_model 可用 L1 score 做更精准的压缩
```

### 10.4 渐进式压缩策略

| 上下文使用率 | 策略 | 效果 |
|------------|------|------|
| < 30% | 不压缩 | 原样传递 |
| 30% - 50% | 不压缩 | 原样传递 |
| 50% - 85% | 温和压缩 | 按 L1 score 从高到低，将旧工具结果替换为摘要 |
| 85% - 95% | 激进压缩 | 删除最旧 30% 消息 |
| > 95% | 紧急截断 | 保留最新 60% 消息 |

## 十一、架构约束：Guardian + Harness 三层防御

### 11.1 防御纵深

```
用户消息
    │
    ├─ ① Guardian（before_agent）     ← 输入层防御
    │   → LLM 二分类：安全 / 危险
    │   → 危险 → 终止整个 agent
    │
    ├─ ② HarnessSecurity（wrap_tool_call）← 执行层防御
    │   → 受保护路径检查（.env, .key, .ssh）
    │   → 危险命令检查（rm -rf, DROP TABLE）
    │   → 自定义规则检查（harness_rules.yaml，热重载）
    │   → 违规 → 拦截，不执行工具
    │
    └─ ③ HarnessReview（after_agent）  ← 输出层审计
        → LLM 四维评估：质量/幻觉/工具使用/问题
        → 结果存入 session metadata
```

### 11.2 自定义规则示例

**`config/harness_rules.yaml`：**

```yaml
rules:
  - name: "禁止删除 wiki 页面"
    tool: "terminal"
    command_contains: "rm -rf wiki/"
    action: block
    message: "不允许批量删除 wiki 页面"

  - name: "禁止修改 raw 目录"
    tool: "terminal"
    command_contains: "raw/"
    action: block
    message: "raw/ 目录为只写（append-only），不可修改"
```

规则修改后**立即生效**，无需重启后端。

## 十二、知识熵管理：防止知识库退化

### 12.1 熵的来源

| 熵源 | 表现 | 应对 |
|------|------|------|
| 重复页面 | 同一篇论文被多次导入 | `register_source` SHA-256 去重 |
| 悬空引用 | 引用了被删除的页面 | `lint_wiki` 定期检查 |
| 孤儿页面 | 没有任何页面引用 | `lint_wiki` 检测 + `backfill` 补全 |
| 过时信息 | 论文结论被后续工作推翻 | `paper-update` skill 更新 |
| 碎片化 | 概念页面过多、缺乏整合 | 条件性 survey/comparison 自动创建 |
| 上下文污染 | 旧对话中的错误信息被记忆 | L1 去重（哈希 + merge/store） |

### 12.2 熵治理工具

**lint_wiki（健康检查）：**

```
Red:    索引与实际页面不一致 → 必须修复
Yellow: 悬空引用（引用了不存在的页面）→ 应该修复
Blue:   孤儿页面（没有被引用）→ 建议修复
```

支持 `auto_fix=True`（自动修复）和 `backfill=True`（LLM 补全缺失页面）。

**rebuild_index（重建索引）：**

重新生成 `wiki/index.md`、`context_brief.md`、`open_questions.md`，确保元数据与实际页面一致。

**retry-lesson-capture（失败学习）：**

将失败经验写入 SKILL.md 和 MEMORY.md，防止同样的错误重复发生。
